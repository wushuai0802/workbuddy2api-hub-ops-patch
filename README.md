## 2026-10-26 风控状态与早期错误

区域暂停的原到期时间和窗口内账号哈希写入`usage/restriction-state.json`，重启后继续原期限，不重新起算。文件有大小/条数限制，采用原子写入；损坏、符号链接或写入失败会在`/health/retry`报告，写入失败时内存保护继续。已有账号自身冷却与显式关闭配置保留，不从历史报错追补限制。

每日活跃收到明确11140后也写入原账号冷却，并通知正在运行的网关区域状态；账号或区域受限时，任务入口不会发出新请求。网页活跃停止后续轮次，不记当日完成；普通配额/内容拒绝不误判风控，111400不会因数字前缀误中11140。定时与手动入口共用这条边界。

模型处理入口的上游拒绝现在也进入观察记录，区分账号风控、区域暂停、普通限流和连接失败；新增`stage=entry/response`及适用时的`http_status`，成功响应仍只记一个请求，不增加用量行。空池在三协议统一为503并与账本一致。观察文件不保存原始报错、提示词、Key或账号身份，业务完成仍标为未测量。

新增21项回归（10持久化、4入口、7任务），包含新进程、并发、损坏/超大文件、三协议、同批次停止及真实记账路径。原生上游账号风控与其他供应商的传输故障不因这些修复消失。

## 安装

先保存旧镜像、源码、配置和数据，在新目录获取两个准确版本：

~~~sh
git clone --depth 1 --branch v1.9.2-ops.20261031.1 https://github.com/wushuai0802/workbuddy2api-hub-ops-patch.git ops-patch-v192
git clone --depth 1 --branch v1.9.2 https://github.com/ardeyouxipianyi/workbuddy2api-hub.git workbuddy2api-hub-v1.9.2
git -C workbuddy2api-hub-v1.9.2 rev-parse HEAD
python3 -B ops-patch-v192/apply.py --verify-package
python3 -B ops-patch-v192/apply.py --target ./workbuddy2api-hub-v1.9.2 --dry-run
~~~

提交必须匹配上面的完整SHA。预检通过后，按[安装指南](docs/INSTALL.md)暂停唯一目标服务、应用完整补丁、构建并定向切换。已有旧补丁（包括v1.7.3）不能直接叠加；不要删除状态/备份绕过检查。旧Release/tag继续保留。

公共默认请求体上限保持官方16MiB；确有大历史需求时显式设置 `WB_MAX_PAYLOAD_BYTES=52428800`，评估并发内存。新版可能重建用量checkpoint缓存，历史JSONL应保留。调度、出口退避、权重、轻量签到模型等仍由使用者的既有设置决定，本补丁不代你启用。

## 验证与边界

离线runner包含225组Python回归（50组补丁及全部175组官方Python），另有59组官方Node及2组补丁Node。本版新增3项终态/用量/名额及401缓存联动，继承此前13项v1.9.0、21项风控/入口、日志饱和、Windows首帧/取消、心跳及认证保护。CI检查Linux3.11/3.12与Windows3.11，实际结果见[验证记录](docs/VERIFICATION.md)。

测试使用合成账号、空数据和本机HTTP，不含真实会话。检测仍以单次生成为范围，尚无通用跨工具回合业务进展熔断。健康、模块指纹或离线测试不等于真实长会话输出质量验收。

`/health/retry` 报告版本、来源与固定源码指纹，并提供 `observations` 请求/尝试分组。默认窗口从本进程启动开始，可用 `since/until` Unix时间戳和 `model` 筛选。`legacy_window` 明确原历史统计范围；合法输出恢复与业务完成分别说明。新观察文件上限约30MiB，接口最多扫描20000行，报告保留范围和截断状态；只保存固定原因码、数值、版本和网关生成的请求ID。`WB_OPS_OBSERVE=0` 关闭新文件写入。

端点遵循原API-key鉴权；没有设置Key时不会额外添加鉴权。提交问题时提供脱敏版本、协议、错误码和最小合成例子，不上传账号、完整配置、历史或备份镜像。
