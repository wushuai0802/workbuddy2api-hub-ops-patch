纳入v1.7.13～1.7.15的出站身份/账号连接隔离、工具Schema与图片/配对修复、积分护栏、可配置排程及冷却展示。保留防复读与期限保护，完善401同号重试、定址账号恢复隔离，以及管理型部署的停止保护。

## v1.7.17 升级与修复

Chat流式响应在客户端尚未收到任何字节时，对同一账号、同一出口重开一次；重试成功不抹掉首次断流留下的出口退避记录，只有完整读完的干净流才清零。出口成功记账从“拿到响应头”改到“读完正文”。模型级5xx（11134/11102/11150/11158/11129等）只停手并原样返回，不再给账号记失败或熔断整池。

账号日限额为0时也会无条件推送，关闭限额立即生效；Codex一键配置改用内联bearer token，避免GUI未继承环境变量时报错；新增X-Private-Data三身份覆盖、积分包到期统一按长期有效显示、OpenRouter按模型估价系数、成长任务手动领取、免费账号不可用标记、`WB_DEPLOY_MODE`、按任务小时排程及completion tokens吞吐统计。

仅reasoning没有正文的回复现在按失败结束（流式`response.failed`、非流式502），不再伪装completed；新增`WB_DEFAULT_REASONING_EFFORT`。面板修复空数据悬停、迟到响应、移动端错行、区块导航按钮文字混入标题及手机号脱敏。网关模型清单支持勾选；DSH一键配置只替换`wb-proxy`段并保留其他provider与注释。

本补丁继续保留：DeepSeek混合/引用复读检测与一次安全恢复、推理别名预算、工具图片兼容、六路径失败终态与原始用量快照、401有界刷新与绝对期限、连接池租约、首帧包装、SSE分块和安装/回滚保护。默认关闭403提示词降级，保持客户端指令；需要时可显式设置`WB_OPS_ALLOW_PROMPT_DEGRADE=1`。

## v1.7.16 升级与修复

统计轮询在同一个15秒桶内复用请求URL，手动选择区间仍使用精确时间；迟到的成功或错误响应不覆盖新数据及加载状态。环比的日历起点也取该请求的时间，修复跨日/周/月时出现倒置区间的问题。

国内版可显式设置`WB_CN_CHAT_UPSTREAM=https://www.workbuddy.cn`，会影响国内桌面/CLI对话、刷新、目录及成长任务；账号`X-Domain`和国际版不变。默认继续原地址，不修改现有路由，也不主动测试真实模型。

日志按钮使用原生浏览器日志页，Windows/Linux/NAS均可打开，不再创建服务端窗口；管理型部署仍拒绝进程内停止。桌面停止须先收到明确确认，再以有超时的健康探测复核；401/403/断网、无确认、探测超时/HTTP错误或仍在运行时保持轮询。当前看板与Python代码一起安装/回滚和校验指纹。

401只走有界请求刷新，不叠加后台三次重试；成功后优先原账号，并重新检查模型禁用/可用性。刷新超时、响应过大及HTML代理401不再误标为凭据过期，错误正文也受原期限与4096字节上限约束。新增`/u/<ref>/v1/...`定址路由在跨线程恢复中不会丢失账号限制，也不会自动转积分版。

保留上游403/11140限制持久化与整池暂停、证书校验失败不轮换、可选私有CA，以及工具Schema规整/插入消息配对/结构化图片。DeepSeek工具消息图片仍按兼容规则处理，用户图片保持。额度扫描默认空名单；原生窗口探针默认开启，会在额度重置时发起模型请求。希望保持旧版无主动探针行为时，部署前显式设置`settings.window_probe=false`。安装器不改配置或签到时段。

## 既有 v1.7.10 变更

纳入Messages与积分回退面板开关、每API Key并发限制（0/空值不限，超限429）及DSH视觉配置。免费额度回退积分版默认关闭，开启后可能真实消耗积分；面板开关与对应环境变量为OR关系，环境变量为1时面板关闭不能抵消。

补齐原生错误计账在六条协议路径的行为：上游`finish_reason=error`统一返回失败信号并保留已接收用量，不增加恢复或重放工具。实际计费模型与原请求模型分别记录，经过首帧包装/安全恢复仍正确归属；可选积分回退继承原deadline/账号排除条件。已有混合/引用守卫、历史、图片、401、SSE及连接租约保护保持。

## 保留的v1.7.6行为

上游默认把`gpt-5.6-terra / gpt-5.6-luna / gpt-5.3-codex`重定向到`deepseek-v4.1-flash`。它只按模型名匹配，主动请求这些模型也会被改写，不识别请求是否来自后台。`WB_BACKGROUND_MODEL_NAMES=""`可关闭；名单和目标均可自定义。

`/v1/messages`、`/messages`及其count_tokens端点默认在转发前返回400；原API Key鉴权仍先执行。原因是转换层仍不透传`cache_control`，该更新没有修复缓存等价性。显式`WB_ENABLE_ANTHROPIC_MESSAGES=1`保留旧接口行为。升级前按已有调用决定兼容设置；本公开包保留上游默认，不自动启用这项协议。

## 安装

先保存旧镜像、源码、配置和数据，在新目录获取两个准确版本：

~~~sh
git clone --depth 1 --branch v1.7.17-ops.20261020.1 https://github.com/wushuai0802/workbuddy2api-hub-ops-patch.git ops-patch-v1717
git clone --depth 1 --branch v1.7.17 https://github.com/ardeyouxipianyi/workbuddy2api-hub.git workbuddy2api-hub-v1.7.17
git -C workbuddy2api-hub-v1.7.17 rev-parse HEAD
python3 -B ops-patch-v1717/apply.py --verify-package
python3 -B ops-patch-v1717/apply.py --target ./workbuddy2api-hub-v1.7.17 --dry-run
~~~

提交必须匹配上面的完整SHA。预检通过后，按[安装指南](docs/INSTALL.md)暂停唯一目标服务、应用完整补丁、构建并定向切换。已有旧补丁（包括v1.7.3）不能直接叠加；不要删除状态/备份绕过检查。旧Release/tag继续保留。

公共默认请求体上限保持官方16MiB；确有大历史需求时显式设置 `WB_MAX_PAYLOAD_BYTES=52428800`，评估并发内存。新版可能重建用量checkpoint缓存，历史JSONL应保留。调度、出口退避、权重、轻量签到模型等仍由使用者的既有设置决定，本补丁不代你启用。

## 验证与边界

离线runner包含175组Python回归（36组补丁及全部139组官方Python），另有49组官方Node及2组补丁Node；新增阶段期限、连续前缀、默认恢复提示、匿名证据持久化及可选日志库测试；面板使用官方Node合成DOM测试。CI检查Linux3.11/3.12与Windows3.11，实际结果见[验证记录](docs/VERIFICATION.md)。

测试使用合成账号、空数据和本机HTTP，不含真实会话。检测仍以单次生成为范围，尚无通用跨工具回合业务进展熔断。健康、模块指纹或离线测试不等于真实长会话输出质量验收。

`/health/retry` 报告版本、来源与固定源码指纹，并提供 `observations` 请求/尝试分组。默认窗口从本进程启动开始，可用 `since/until` Unix时间戳和 `model` 筛选。`legacy_window` 明确原历史统计范围；合法输出恢复与业务完成分别说明。新观察文件上限约30MiB，接口最多扫描20000行，报告保留范围和截断状态；只保存固定原因码、数值、版本和网关生成的请求ID。`WB_OPS_OBSERVE=0` 关闭新文件写入。

端点遵循原API-key鉴权；没有设置Key时不会额外添加鉴权。提交问题时提供脱敏版本、协议、错误码和最小合成例子，不上传账号、完整配置、历史或备份镜像。
